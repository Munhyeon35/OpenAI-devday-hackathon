# 공공데이터 병원 후보 조회

`POST /api/hospitals/candidates`는 구급차 좌표와 명시적으로 선택한 조건을 받아
국립중앙의료원 데이터를 병원 ID(`hpid`)로 결합합니다. `OPENDATA_API_KEY`는
프로젝트 루트 `.env.local`에 설정하며 서버에서만 사용합니다. 인코딩 키와 디코딩 키를
모두 지원합니다. 키 발급 외에 해당 서비스의 활용신청 승인이 필요합니다.

- 공식 서비스: https://www.data.go.kr/data/15000563/openapi.do
- 매핑 기준: 위 페이지의 `NIA-IFT-OpenAPI활용가이드-01.국립중앙의료원-응급의료정보조회서비스_V13.hwp`
- 서버 호스트: `https://apis.data.go.kr/B552657/ErmctInfoInqireService`

구형 예제의 11개 시술 코드와 최신 가이드의 27개 시술 코드는 의미가 다릅니다.
예를 들어 V13에서 `mkioskty1`은 심근경색 재관류중재술, `mkioskty2`는 뇌경색
재관류중재술, `mkioskty11`은 성인 위장관 응급내시경입니다.
지원 조건 전체는 `src/lib/hospitals.ts`에 있습니다.

## 사용

`npm run dev` 후 localhost 대시보드의 사이드바 하단 **환자 추가**를 누릅니다.
신규 접수가 먼저 생성되고 기존 환자 평가 대화상자가 자동으로 열립니다.
환자 정보와 대화상자 아래쪽 구급차 좌표·진료 조건을 입력한 후 **완료**하면
실제 공공데이터 후보 최대 10곳이 지도와 목록에 **전화 전**으로 표시됩니다.
현재 선택한 접수 좌표가 초기값이며 변경할 수 있습니다. 환자 증상을 자동으로
진단하거나 시술로 변환하지 않습니다. 필요한 조건은 운영자가 선택합니다.

**불러오기** 옆 데모 선택에서 두 가지 가상 환자 케이스를 선택할 수 있습니다.
- **서울 · 흉통**: 58세 남성, 서초역 좌표, 내과·심근경색 재관류중재술·CT·일반 응급병상
- **부산 · 편측 마비·언어장애**: 67세 여성, 부산진구 서면 인근 좌표(35.1577, 129.0592), 신경과·뇌경색 재관류중재술·CT·일반 응급병상

선택 후 **불러오기**를 눌러야 환자·좌표·조건이 함께 채워집니다. 두 케이스 모두 반경 20km,
최대 10곳이며 확인 필요 후보도 포함합니다. 입력창 취소 시 접수는 ‘입력 중’으로 남습니다.
조회 실패 시 ‘다시 조회’, 후보 없음 시 ‘입력·수정’에서 조건을 변경할 수 있습니다.
다시 조회하면 기존 후보와 데모 통화 진행을 초기화하며, 오래된 조회 응답은 무시합니다.
검색 중에는 지도 중앙에 진행 상태를 표시하며 기존 지도 시점을 유지합니다.
완료된 후보 범위가 바뀔 때만 한 번 부드럽게 이동하고, 필요한 경우 축소합니다.
동일한 후보를 다시 조회하면 사용자가 조정한 위치·확대 정도를 유지합니다.
동작 줄이기 설정에서는 지도 이동 애니메이션을 생략합니다.

**일괄 전화 시작**은 표시된 후보의 데모 통화를 명시적으로 시작합니다.
실제 발신은 없으며, 공공데이터의 수용 미확정 정보와 시뮬레이션 통화 결과는 별개입니다.
새 접수·수정 내용·통화 진행은 메모리에만 유지되어 새로고침하면 초기화됩니다.

로컬 API 예시(전화 발신 없음):

```bash
curl http://localhost:3000/api/hospitals/candidates \
  -H 'Origin: http://localhost:3000' \
  -H 'Content-Type: application/json' \
  --data '{"latitude":37.5665,"longitude":126.978,"radiusKm":20,"limit":10,"departments":["D003"],"procedures":["mkioskty2"],"equipment":["hvctayn"],"beds":["hvec"],"includeUnknown":true}'
```

`latitude`, `longitude`는 필수입니다. `radiusKm`는 1~100(기본 20), `limit`는
1~30(기본 10)입니다. 진료과·시술·장비·병상 배열은 생략할 수 있고, 선택한 모든
조건을 함께 적용합니다. `includeUnknown`의 기본값은 `true`입니다.
기존 운영자 프록시와 같이 localhost 및 동일 출처 전용입니다. 공개 배포 전에는
별도 운영자 인증과 공유 호출량 제한을 추가해야 합니다.

## 조회 및 판정

1. `getEgytListInfoInqire`의 전국 병원 목록을 끝까지 페이지 조회하고 좌표로 반경을 계산합니다.
   인접 시·도 경계를 넘는 병원도 검색합니다. 위치조회 API는 반경을 지정할 수 없어
   전국 목록에서 직접 계산합니다. 잘못되거나 없는 병원 좌표는 제외합니다.
2. `getEmrrmRltmUsefulSckbdInfoInqire`에서 병상·장비를 조회합니다.
   시술 조건이 있을 때는 `getSrsillDissAceptncPosblInfoInqire`도 조회합니다.
   두 조회는 `STAGE1`, `STAGE2`를 빈 값으로 전달하여 전국 데이터를 요청합니다.
3. 진료과 조건은 `getEgytListInfoInqire`의 `QD`별 병원 ID로 교차 확인합니다.
4. 명시적인 불가(`N`)나 최신 병상 수 0 이하인 필수 조건은 후보에서 제외합니다.
   누락값·알 수 없는 코드·조회 실패는 `unknown`으로 처리합니다.
5. 선택 조건을 모두 충족한다고 보고된 후보가 먼저, 그 안에서는 직선거리 순으로
   정렬합니다. 결과 수 제한은 필터링 이후 적용합니다.

병상 보고 시각 `hvidate`는 한국 시간으로 해석합니다. 20분 초과, 시각 누락 또는
미래 시각이면 병상·장비 조건을 `unknown`으로 바꿉니다. 20분은 이 앱의 보수적인
표시 기준이며 제공기관의 갱신 보장 주기가 아닙니다. 원본 병상 수와 보고 시각은
함께 반환합니다. 빈 숫자는 0으로 바꾸지 않습니다.

시술 데이터의 `MKioskTy*Msg` 부가조건이 있는 `Y`는 연령 등의 확인이 필요하므로
`unknown`으로 처리합니다. 개별 시술 갱신 시각은 가이드에서 제공되지 않아
실제 수용 판단의 최신성을 보장하지 않습니다. 진료과 등록도 당직 의료진 확보를
뜻하지 않습니다. 모든 후보의 `acceptance`는 `unconfirmed`입니다.

## 응답

- `candidates`: 병원명, 좌표, 주소, 응급실·대표 전화, 기관 분류, 직선거리,
  조건별 `checks`, 병상 수, 병상 보고 시각, 시술 부가조건
- `match`: `reported_match`(선택 조건 충족 보고) 또는 `needs_confirmation`
- `distanceKm`: 후보 반경 계산에 사용한 직선거리(기존 의미 유지)
- `roadRoute`: 경로 조회 성공 시에만 제공. `provider: "OSRM"`, `distanceKm`(도로 km),
  `durationSeconds`(예상 초), `calculatedAt`(경로 서비스 조회 시각)
- `distanceType`: 화면 거리 종류 `road`, `mixed`, `straight_line`
- `routing`: `provider: "OSRM"`, `status: "complete" | "partial" | "unavailable"`
- `checks[].status`: `reported_available`, `reported_unavailable`, `unknown`
- `totalNearby`, `totalMatched`: 반경 내 병원 수와 필터링 후 후보 수
- `sourceRetrievedAt`: 각 원천 데이터의 조회 시각
- `warnings`: 부분 조회 실패, 수용 확인 필요 등

공공데이터 후보 선정 뒤 OSRM Table API로 각 후보까지의 자동차 도로 거리와 예상 시간을
한 번에 조회합니다. 좌표 순서는 경도, 위도이며 구급차 한 곳을 `sources=0`, 병원 각각을
`destinations=1;2;…`로 지정하므로 여러 병원을 차례로 방문하는 경로가 아닙니다.
병원은 공공데이터의 조건·직선거리 기준으로 먼저 선정하며, 표시된 후보 안에서 도로 거리와
예상 시간으로 정렬합니다. 전체 지역에서 도로 기준 최적 병원을 보장하는 검색은 아닙니다.

경로가 있는 후보는 목록과 지도에 **도로 거리·예상 분**으로 표시합니다. 시간은 초 단위
응답을 분 단위로 올림(최소 1분)하며 실시간 교통·구급차 특례 주행을 반영하지 않습니다.
연결 불가, 경로 없음, 잘못된 응답, 도로에 맞춘 위치가 원래 좌표에서 250m를 초과하는
경우는 **직선거리·시간 미확인**으로 표시합니다. 도로 거리 정렬에서 경로 미확인 후보는
확인된 후보 뒤에 놓습니다. 실패 시에도 병원 후보와 수용 정보는 유지합니다.

추가 키 없이 `https://router.project-osrm.org/table/v1/driving/…`를 사용합니다.
서버 요청에 환자 정보·진료 조건·공공데이터 키를 포함하지 않습니다. 정밀 좌표 URL이
Next fetch 로그에 남지 않도록 native HTTPS로 요청합니다. 요청당 최대 10초,
256KiB 응답 제한을 적용하며 자동 재시도하지 않습니다. 요청을 직렬화하고 프로세스당
최소 1.1초 간격을 유지하며, 최대 50개의 응답을 5분 동안 메모리에 캐시합니다.
캐시 재사용 시 원래 경로 조회 시각을 유지합니다.

[OSRM Table API](https://project-osrm.org/docs/v5.22.0/api/#table-service) ·
[공개 데모 서버 정책](https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server)
공개 서버는 비상업적 시연을 위한 것으로 서비스 가용성·데이터 갱신을 보장하지 않습니다.
운영 환경에는 자체 호스팅 또는 별도 경로 API가 필요합니다.

공공데이터 조회 결과는 ‘전화 전’이며 자동으로 통화를 시작하지 않습니다.
시뮬레이션 실행 후의 ‘이송 가능’ 표시는 데모 대화 결과이며 실제 확답이 아닙니다.

기관 목록은 서버 메모리에 5분, 병상·시술 자료는 30초 캐시합니다. 페이지 조회가
중단되면 완전한 목록처럼 반환하지 않습니다. 전체 병원 조회 실패는 502/503으로,
병상·시술의 부분 실패는 경고와 `unknown`으로 전달합니다. 브라우저 응답은
`Cache-Control: no-store`이며 키·상류 응답 전문·네트워크 오류 객체를 노출하지 않습니다.

## 검증

`npm run test:hospitals`는 XML/인증 오류, 페이지네이션, 코드 매핑, 조건 교집합,
반경, 누락·오래된 정보, 부가조건, 요청 검증 및 오류 비노출을 모의 데이터로 검증합니다.
실제 연결 여부는 유효한 키를 설정한 뒤 후보 조회 결과로 별도 확인해야 합니다.

`npm run test:patient-workflow`는 신규 접수, 전화 전 유지, 명시적 일괄 시작과 중복 방지,
접수별 격리, 늦은 응답 무시, 실패·빈 결과, 재조회 시 초기화와 ETA 미생성을 검증합니다.

`npm run test:hospital-routes`는 좌표 순서·행렬 대응, 단위 변환, 전화 전 유지, 부분 실패,
잘못된 응답, 과도한 도로 좌표 보정, 오류 비노출, 원래 조회 시각 보존과 정렬을 검증합니다.
